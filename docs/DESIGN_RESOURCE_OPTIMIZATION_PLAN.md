# LeeU2 作品集网站设计与资源管理优化方案

## 0. 需求转述

本方案基于当前 LeeU2 静态作品集网站的实际结构，结合已有优化建议，重新整理一套更适合长期更新图片集、管理不同作品版块、保持视觉统一和内容秩序的整体优化蓝图。

本方案不重点讨论具体代码怎么写、用什么框架实现、技术细节如何落地，而是回答以下问题：

- 这个网站未来应该被整理成什么样子？
- 各个版块之间应该如何划分？
- 图片、视频、博客、联系方式等资源应该如何管理？
- 作品集命名、目录、封面、排序、隐藏状态应该如何规范？
- 如果以后频繁更新图片集，理想的维护流程应该是什么样？
- 前端排版如果通过图形化界面调整，最终体验应该如何？

换句话说，这是一份面向“设计逻辑、内容资产管理、作品集更新流程”的完整优化方案。

## 1. 总体优化目标

当前项目已经具备清晰的作品集雏形：有首页、妆发、摄影、Secret、Films、Blog、Contact 等版块，也已经将公共 CSS/JS 资源集中到了 `assets/` 中。

下一阶段优化的重点，不是改变网站气质，而是让它更容易长期维护。

优化后的理想状态是：

1. 网站仍然保持 LeeU2 当前的黑底、红色、图片主导、个人化表达的视觉气质。
2. 所有作品集都有统一的命名、封面、图片排序和展示规则。
3. 新增一组图片时，不再需要手动改多个 HTML 页面。
4. 首页、分类页、详情页都从同一份内容资料中读取作品信息。
5. 图片资源有清晰的原图、展示图、缩略图管理方式。
6. 可以通过一个本地可视化编辑页面调整封面、排序、是否展示、所属版块等内容。
7. 网站从“页面堆叠”逐步变成“作品资料库 + 统一展示系统”。

## 2. 优化后的整体网站形态

优化完成后，网站可以被理解为四层：

```text
第一层：品牌与视觉系统
黑底、红色、导航、字体、图片边框、整体观感

第二层：内容版块系统
Home / Makeup&Hair / Photo / Secret / Films / Blog / Contact

第三层：作品资料系统
每个作品集的标题、分类、封面、图片列表、排序、展示状态

第四层：资源资产系统
图片原图、展示图、缩略图、视频封面、联系页图片、博客配图
```

也就是说，未来网站不再主要靠每个 HTML 页面手写内容，而是先维护好“作品资料”和“图片资产”，页面只是把这些内容以统一风格展示出来。

## 3. 版块划分优化

### 3.1 保留现有一级版块

当前一级版块划分是合理的，建议继续保留：

| 版块 | 定位 | 未来优化方向 |
| --- | --- | --- |
| Home | 精选入口 | 展示全站最重要、最新或最能代表风格的作品 |
| Makeup&Hair | 妆发作品 | 作为妆发创作的正式作品入口 |
| Photo | 摄影作品 | 作为摄影作品的正式作品入口 |
| Secret | 私人/实验项目 | 保留更自由、更私密、更氛围化的内容属性 |
| Films | 影像作品 | 展示视频封面和外部播放入口 |
| Blog | 文字记录 | 用于文章、创作记录、阶段性想法 |
| Contact | 个人介绍 | 展示个人信息、联系方式和社交入口 |

这些版块已经和网站内容类型高度匹配，不建议为了“更现代”而拆得过细。

### 3.2 首页的角色重新定义

当前首页是混合展示多个分类中的图片。优化后，首页建议定位为：

> 全站精选橱窗，而不是全部内容索引。

首页应该只展示以下内容：

- 最能代表个人风格的作品。
- 最新更新的作品。
- 当前最想被看到的作品。
- 少量电影/视频封面。

首页不需要展示所有作品，也不需要承担完整分类导航的职责。完整浏览应该交给 Makeup&Hair、Photo、Secret 等分类页。

### 3.3 分类页的角色重新定义

分类页建议统一成为“作品集封面墙”。

每个分类页只展示该分类下的作品集入口，而不是展示所有详情图片。

例如 Photo 页面未来应展示：

```text
Photo
├── Mancheng Room
├── Yellow Stone 1
├── Yellow Stone 2
├── Genderless
├── Blue Light
└── Heshu House
```

每个作品集入口包含：

- 封面图。
- 项目标题。
- 可选日期。
- 可选短描述。
- 可选标签。

### 3.4 详情页的角色重新定义

详情页是单个作品集的完整展示页。

每个详情页应该包含：

- 项目标题。
- 所属分类。
- 封面或首图。
- 完整图片序列。
- 可选文字说明。
- 可选拍摄/妆发/模特/地点/日期信息。

当前项目的详情页以图片为主，这个方向可以保留。文字不需要强加，但数据结构上应给它预留位置。

## 4. 目录规范优化

### 4.1 建议保留的目录

当前目录结构整体可以保留，不需要大幅推翻：

```text
LeeU2Test/
├── index.html
├── navbar.html
├── assets/
├── pic/
├── makeup/
├── photo/
├── secret/
├── films/
├── blogs/
├── contact/
├── makeupproj/
├── photoproj/
└── secretproj/
```

这样做的好处是：

- 不破坏当前网站已有路径。
- 已有页面和图片链接不用一次性全部迁移。
- 后续可以逐步优化，不需要重建整站。

### 4.2 建议新增的数据目录

建议新增一个专门管理内容资料的目录：

```text
assets/data/
├── projects.json
├── films.json
└── blogs.json
```

它的意义不是技术上的“数据库”，而是内容台账。

未来所有作品集都应先登记到内容资料中，再由页面展示。

### 4.3 图片资源目录优化

当前图片资源位于 `pic/`，这个目录建议继续作为媒体资产库。

未来建议逐步整理成：

```text
pic/
├── makeup/
│   └── makeup10_ProjectName/
├── photo/
│   └── photo10_ProjectName/
├── secret/
│   └── secret9_ProjectName/
├── film/
└── contact/
```

对于新的图片集，建议每组作品使用独立文件夹，不要把不同项目图片混放。

### 4.4 图片尺寸目录建议

如果后续图片越来越多，建议每个作品集内部再分三类：

```text
photo10_ProjectName/
├── full/
├── display/
└── thumb/
```

含义：

- `full/`：原尺寸或高质量版本，用于保存和放大查看。
- `display/`：网页正常展示版本。
- `thumb/`：封面和列表缩略图版本。

如果短期不想增加复杂度，也可以先继续使用当前单层图片目录，只在后续图片数量明显增加时再拆分。

## 5. 命名规范优化

### 5.1 作品集 ID 命名

每个作品集应该有一个稳定 ID，用于连接目录、页面、封面和数据。

建议格式：

```text
{category}{number}
```

示例：

```text
makeup10
photo10
secret9
film6
```

这个 ID 不建议频繁修改。标题可以变，ID 最好不变。

### 5.2 作品目录命名

建议格式：

```text
{id}_{ProjectName}
```

示例：

```text
photo10_NightGarden
makeup10_SilverLine
secret9_RedRoom
```

命名建议：

- 前半部分使用稳定 ID。
- 后半部分使用英文项目名。
- 英文项目名使用大驼峰或首字母大写单词。
- 不建议使用空格。
- 尽量避免特殊符号，如 `&`、中文标点、括号。

当前已有目录如 `makeup1&2_LesFleursDuMal` 可以保留，不必强行迁移。新内容按新规范执行即可。

### 5.3 图片文件命名

建议格式：

```text
{id}_{index}.webp
```

示例：

```text
photo10_0.webp
photo10_1.webp
photo10_2.webp
```

推荐规则：

- 从 `0` 或 `1` 开始均可，但同一个项目内要统一。
- 封面图不一定必须是 `_0`，封面应由资料文件指定。
- 不建议把最终展示顺序完全绑死在文件名里，排序应该可以在编辑器中调整。

### 5.4 页面命名

在保留当前结构的情况下，详情页仍可使用：

```text
photoproj/photo10.html
makeupproj/makeup10.html
secretproj/secret9.html
```

长期来看，详情页可以逐步变成统一页面：

```text
project.html?id=photo10
```

但从设计和资源管理角度看，用户最终感受到的是：

- 每个作品集都有独立入口。
- URL 稳定。
- 分类关系清晰。
- 不需要关心背后是一页模板还是多个 HTML。

## 6. 作品资料管理方案

### 6.1 每个作品集应包含的信息

未来每个作品集建议统一登记以下信息：

| 字段 | 含义 |
| --- | --- |
| ID | 作品集唯一标识，如 `photo10` |
| 标题 | 展示给访客看的名称 |
| 分类 | makeup / photo / secret |
| 封面图 | 分类页和首页使用的主图 |
| 图片列表 | 详情页展示的所有图片 |
| 首页展示 | 是否出现在 Home |
| 分类页展示 | 是否出现在分类页 |
| 图片可见性 | 单张图片是否隐藏 |
| 排序 | 首页、分类页、详情页中的顺序 |
| 日期 | 可选，作品时间或发布日 |
| 标签 | 可选，如 portrait / room / sea / red |
| 描述 | 可选，项目说明 |

### 6.2 作品展示状态

建议把展示状态分成三层：

1. **公开展示**

   出现在分类页和详情页。

2. **首页精选**

   出现在首页，作为重点推荐。

3. **隐藏但保留**

   图片或作品仍保存在资源库中，但暂不展示。

这样可以替代当前用 HTML 注释隐藏图片的方式。

### 6.3 封面管理

封面不建议默认使用第一张图，而应该单独指定。

原因：

- 第一张图适合详情页开场，不一定适合做封面。
- 首页封面和分类页封面可能需要视觉冲击更强的图片。
- 有些作品集的最佳封面可能是中间某张图。

未来理想状态：

- 每个作品集可以选择一张主封面。
- 首页可以使用同一张封面，也可以选择独立首页封面。
- 分类页封面保持统一比例和视觉秩序。

## 7. 图片资源管理方案

### 7.1 图片进入项目后的标准流程

未来新增图片集时，理想流程是：

1. 创建作品集文件夹。
2. 放入图片。
3. 统一转成网页适合的格式和尺寸。
4. 选择封面。
5. 调整图片顺序。
6. 标记需要隐藏的图片。
7. 决定是否显示在首页。
8. 保存后网站自动更新展示。

从使用体验上看，维护者不需要思考 HTML 写在哪里，只需要管理作品资料和图片。

### 7.2 图片质量分层

建议将图片资产分为三种用途：

| 类型 | 用途 | 特点 |
| --- | --- | --- |
| 原始收藏图 | 存档、备份 | 尺寸最大，不一定直接上网页 |
| 网页展示图 | 详情页观看 | 质量高，但体积适中 |
| 缩略图 | 首页/分类页封面 | 加载快，适合列表展示 |

这样既能保留作品质量，也能保证网站浏览速度。

### 7.3 图片可见性管理

当前项目中有些图片通过 HTML 注释隐藏。优化后建议变成可管理状态：

```text
显示
隐藏
仅存档
仅详情页显示
首页精选
```

最终效果：

- 不想展示的图不会被删掉。
- 随时可以重新打开展示。
- 不需要在 HTML 中找注释。
- 图片集更新更像管理相册，而不是修改代码。

## 8. 可视化编辑器设想

### 8.1 编辑器定位

建议未来增加一个仅本地使用的“作品集管理页面”。

它不是给访客看的页面，而是给自己更新网站时用的管理界面。

可以命名为：

```text
admin/gallery-editor.html
```

### 8.2 编辑器应该长什么样

理想界面可以分成三栏：

```text
左侧：作品集列表
中间：图片排序与封面选择
右侧：页面预览
```

左侧用于选择分类和作品集：

- Home 精选
- Makeup&Hair
- Photo
- Secret
- Films
- Blog

中间用于管理当前作品集：

- 拖拽调整图片顺序。
- 点击选择封面。
- 勾选是否首页展示。
- 勾选是否分类页展示。
- 隐藏/显示单张图片。
- 编辑标题和短描述。

右侧用于实时预览：

- 首页显示效果。
- 分类页显示效果。
- 详情页显示效果。

### 8.3 编辑器带来的最终体验

未来更新一个图片集时，你看到的是：

```text
选择 Photo
新建 photo10
拖入图片
选一张作为封面
拖拽调整顺序
隐藏几张暂时不想展示的图
勾选“显示在首页”
保存
```

而不是：

```text
复制一个 HTML
改十几行图片路径
去 photo/index.html 加封面
去 index.html 加首页图
检查路径有没有写错
用注释隐藏图片
```

这就是本次优化最核心的体验差异。

## 9. 前端排版管理方案

### 9.1 保留当前视觉核心

当前网站的核心视觉元素建议保留：

- 黑色背景。
- 红色文字与边框。
- 顶部固定导航。
- 作品图片居中展示。
- 图片 hover 轻微放大。
- 整体留白偏克制。

这些是网站已有气质，不建议为了管理方便而改成普通模板感很强的作品站。

### 9.2 增加可调排版项

未来可视化编辑器中，可以把一些排版参数变成可调整项：

- 首页展示哪些作品。
- 首页作品顺序。
- 分类页作品顺序。
- 详情页图片顺序。
- 某个作品集是否分段展示。
- 图片间距。
- 图片最大宽度。
- 视频封面顺序。

这些调整不应该要求维护者写 CSS，而是通过选择、拖拽、开关完成。

### 9.3 页面展示模式

未来可以为不同作品集提供几种展示模式：

| 模式 | 适合内容 |
| --- | --- |
| 单列大图 | 当前大部分作品，强调沉浸观看 |
| 分段单列 | 有明显章节或不同造型的作品 |
| 封面网格 | 分类页、首页精选 |
| 视频封面 | Films 页面 |
| 文本记录 | Blog 页面 |

默认仍使用当前的单列大图模式。

## 10. 版块与资源之间的关系

优化后，各版块和资源的关系应更清楚：

```text
Home
└── 从所有作品中挑选 featured = true 的内容

Makeup&Hair
└── 展示 category = makeup 的作品集

Photo
└── 展示 category = photo 的作品集

Secret
└── 展示 category = secret 的作品集

Films
└── 展示 film 类型的视频封面和播放链接

Blog
└── 展示文章标题、日期和链接

Contact
└── 展示个人介绍、联系信息和固定图片
```

这样首页和分类页不再是互相复制内容，而是从同一份内容资料中选择不同视角展示。

## 11. 内容更新后的最终工作方式

### 11.1 新增图片集

未来新增一个作品集时，理想工作流是：

```text
准备图片
放入对应分类目录
在编辑器中新建作品集
填写标题
选择分类
选择封面
调整排序
设置展示位置
预览页面
保存
发布
```

### 11.2 调整首页展示

未来调整首页时，理想工作流是：

```text
打开首页精选管理
拖拽调整顺序
勾选/取消某些作品
预览首页
保存
```

### 11.3 隐藏某张图片

未来隐藏图片时，理想工作流是：

```text
进入作品集
找到图片
关闭“显示”
保存
```

图片仍然保留在项目中，只是不在网站中展示。

### 11.4 更换封面

未来更换封面时，理想工作流是：

```text
进入作品集
点击某张图
设为封面
保存
```

分类页和首页会自动使用新封面。

## 12. 视觉和内容规范建议

### 12.1 首页规范

首页建议保持克制，不展示过多内容。

建议：

- 首页精选数量控制在 8 到 16 个作品入口之间。
- 尽量避免同一作品集连续出现太多张图。
- 首页优先展示跨分类代表作品。
- Films 可以保留少量视频封面，但不要压过图片作品。

### 12.2 分类页规范

分类页建议成为清晰的作品索引。

建议：

- 每个作品集只出现一次。
- 每个作品集使用统一封面。
- 顺序可以按创作时间、推荐程度或视觉节奏排列。
- 暂不展示的作品不删除，只设为隐藏。

### 12.3 详情页规范

详情页建议保留单列观看体验。

建议：

- 图片顺序应服务于观看节奏，而不是完全按文件名。
- 如果一个作品集内部有明显不同部分，可以分段。
- 不建议在详情页加入过多说明文字。
- 标题和必要信息可以轻量出现，但图片仍是核心。

### 12.4 Films 规范

Films 建议保持封面点击播放的方式。

每个视频应管理：

- 标题。
- 封面图。
- B 站播放器地址。
- 展示顺序。
- 是否出现在首页。

### 12.5 Blog 规范

博客建议从纯 HTML 链接逐步转成文章索引。

每篇文章应管理：

- 日期。
- 标题。
- 链接。
- 可选摘要。
- 可选标签。

## 13. 当前项目到优化后项目的变化对比

| 项目 | 当前状态 | 优化后状态 |
| --- | --- | --- |

## 14. 分阶段优化路线

### 第一阶段：整理规范，不改变网站外观

目标：

- 明确版块划分。
- 固定命名规范。
- 建立作品资料台账。
- 明确新增作品集流程。

最终状态：

- 网站看起来几乎不变。
- 但内部内容开始有统一资料来源。
- 新增作品时有明确规则可遵循。

### 第二阶段：图片集管理数据化

目标：

- 首页、分类页、详情页不再重复维护同一组图片。
- 图片封面、排序、隐藏状态都可统一管理。

最终状态：

- 新增作品集只需要维护一次资料。
- 首页和分类页可以自动同步。
- 图片隐藏不再依赖 HTML 注释。

### 第三阶段：本地可视化编辑器

目标：

- 用图形化方式管理作品集。
- 支持拖拽排序、选封面、预览页面。

最终状态：

- 更新网站更接近整理相册。
- 不需要频繁打开 HTML 文件。
- 设计调整更直观。

### 第四阶段：图片资产分层

目标：

- 原图、展示图、缩略图分开管理。
- 页面加载更快。
- 图片质量更稳定。

最终状态：

- 首页和分类页加载更快。
- 详情页图片质量更可控。
- 大量图片集也能保持浏览体验。

### 第五阶段：视觉系统细化

目标：

- 在保留黑红风格的基础上，让页面更稳定、更统一。
- 减少临时内联样式。
- 统一图片、视频、博客、联系页的展示规则。

最终状态：

- 网站风格更成熟。
- 页面之间一致性更强。
- 后续新增版块也能自然融入。

## 15. 优化后的最终样子

优化完成后，LeeU2 网站最终会像一个轻量但有秩序的个人作品档案馆。

访客看到的是：

- 一个风格统一的黑红作品站。
- 首页展示少量精选作品。
- 分类页清楚地区分妆发、摄影、秘密项目、影像和文字。
- 每个作品集都有稳定入口和完整图片展示。
- 图片打开速度更快，观看顺序更舒服。
- 整个网站仍然保留个人化、实验性和私密感。

维护者看到的是：

- 图片按分类和作品集清楚存放。
- 每个作品集有统一资料卡片。
- 封面、排序、隐藏、首页展示都可以集中管理。
- 新增图片集不再需要到处改页面。
- 前端排版可以通过可视化界面调整。
- 网站可以长期扩展，而不会变得越来越乱。

## 16. 核心结论

这个项目下一阶段最重要的优化方向，不是单纯“美化页面”，而是建立一套作品集管理系统。

它应该围绕三件事展开：

1. **内容清楚**

   每个作品属于哪个版块、叫什么、封面是哪张、展示哪些图，都有明确记录。

2. **资源有序**

   图片、视频封面、博客、联系页素材都按类型和作品集管理。

3. **更新轻松**

   新增、隐藏、排序、更换封面、调整首页展示，都可以通过可视化或统一资料完成。

最终目标是让 LeeU2 从一个“能展示作品的网站”，升级为一个“可以长期生长的个人作品档案系统”。
